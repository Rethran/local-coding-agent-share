What is assessed

subtask_done

The orchestrator marked the pinned subtask DONE after the independent verifier passed.

Why: This is the outcome that matters: the agent's own declared verification succeeded and the coordinator agreed. A fluent transcript that never reaches DONE is still a failure.

How (code): Code. Read the copied requirements .state.json after the run. Pass iff the matching subtask status is DONE.

reference_tests_pass

Tests from the historically accepted commit still pass against the code the agent just wrote.

Why: The agent's own tests can be too weak or accidentally rewritten. Overlaying the accepted commit's test files is a cheap substitute for hidden tests. These are regression tests, not independently authored hidden tests.

How (code): Code. After the agent finishes, overlay tests/ files from accepted_commit, then run pytest on those paths in the worktree.

process_budget

The agent finished without looping, blowing the step budget, or drowning in tool errors.

Why: Local models often fail on process before they fail on correctness. A pass that took 80 identical read_file calls is not a prompt you want to keep.

How (code): Code, from run_summary.json. Fail if attempts > 10, steps > 160, any identical tool fingerprint repeats more than 5 times, or tool error rate > 40%.
